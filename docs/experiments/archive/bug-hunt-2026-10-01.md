# Bug hunt — 2026-10-01

Findings from a targeted hunt while v45 trained. Three real bugs,
all fixed and tested.

## 1. RangeTracker fallback violates board exclusion

**Where:** `crates/pkr-subgame/src/range_tracker.rs`,
`update_range_for_action`.

**Bug:** When the renormalization sum collapsed below 1e-12 the
fallback set every entry to `1/N_HANDS`, including hands that share a
card with the board. The module docstring promises board-containing
hands are always zero.

**Impact:** The consumer (`sample_hands_weighted`) samples from the
range. A non-zero mass on an impossible hand would hand the subgame
solver a deal where the "opponent" holds a board card. Never fires on
shipped blueprints (average strategies always leave some mass on
legal buckets), but the tracker is exercised in adversarial sweeps
and fuzz tests where it can.

**Fix:** `7cb8780`. The fallback sets uniform mass over board-free
hands and zero elsewhere. Test added.

## 2. TableProvider zero-sum CDF differs from the exporter

**Where:** `crates/pkr-fuzz/src/provider.rs`.

**Bug:** When `get_average_strategy_slice` returned a zero-sum
strategy, the encoder wrote all-zero CDF bytes. A consumer decodes
that as "bucket 0 gets 100% of the mass" — the opposite of what a
zero strategy should mean.

**Impact:** `pkr-arena` and `pkr-tournament` read through
`TableProvider`. A fuzzed checkpoint with a zero-mass infoset would
be evaluated against a wrong strategy. `pkr_export::writer::quantize_cdf`
already handles this case; `TableProvider` didn't match it.

**Fix:** `bc5ce4e`. `TableProvider` now produces the same CDF as the
exporter on zero-sum, and closes on the last non-zero action
otherwise.

## 3. mirror_to_seat0 doesn't swap dealer

**Where:** `crates/pkr-runtime/src/subgame.rs`,
`mirror_to_seat0`.

**Bug:** Swapped stacks, street_bets, total_invested, folded, hole,
and actor — but not `dealer`. The subgame solver calls
`advance_street_in_place` on street completion, which computes the
next street's first actor as `1 - dealer`. With the wrong dealer, a
mirrored state would hand the first postflop action to the wrong
seat.

**Impact:** River-only subgames never advance a street, so the
shipped config was safe. Turn subgames (`enabled_streets[2]`) DO
advance and would have played the turn with the wrong ordering when
the subgame's actor was in seat 1 of the outer state. Any turn
extension depends on this.

**Fix:** `b867608`. `dealer` is now swapped. Two tests added.

## Not-bugs considered and dismissed

- `RuntimeSession::observe_action` swallowing tracker errors — the
  trait contract says the tracker is advisory; the walker uses the
  caller's state as ground truth. Documented, not a bug.
- `RangeTracker::apply_action` skipping the range update on Fold —
  the folder's range becomes irrelevant once `folded[actor] = true`.
  Any downstream consumer that reads the folded player's range
  would need to handle the fold separately, and none do.
- `arena --hands 0` — `run_eval_harness` returns a zero-decision
  result with `0.0` bb/100, not a division by zero. Cosmetic.
- `tournament` assuming A and B share a tables directory — a real
  footgun if B lives elsewhere, but the fingerprint already catches
  most mismatches. Left as a note, not a fix.
