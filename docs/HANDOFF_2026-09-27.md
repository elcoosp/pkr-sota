### Priority 2 - Fix the e2e test properly

The current design fails because:
- BR walk uses all 1326 opponent hands
- Subgame solve uses `hands_per_range` sampled from a prior
- Mismatch: +14k to +24k mbb regression vs blueprint

The correct design:
- Thread the `RangeTracker` into `sampled_exploitability_with_hook`
- The hook memoizes solves at `(bucket, concrete_hole, history)`,
  so the walk reads a cache instead of re-solving per node
- Cap `max_deals` in the solve to bound per-solve time

Estimated 4-6 hours. Worth doing because it's the last unverified
claim about the subgame stack.

### Priority 3 - Range-aware subgame solving

`SubgameHandle::decide` currently uses uniform ranges. The POC
showed +43 tracked vs +39 wide on the aggressive line; with real
ranges the solve should be stronger. Small change once Priority 2
provides the range plumbing.

### Priority 4 - Verify plateau on a long run

`--stop-on-plateau 5` is live and default. Verify on the next
100M run. Expected savings ~49% of iteration budget.
