## 1. What the codebase does today (analysis — no action required)

### 1.1 Training loop

- **Algorithm:** External-sampling MCCFR (`traverse()` in `crates/pkr-cfr/src/traversal.rs`), 2 traversals per logical iteration (one per seat), 200 bb stacks, blinds 1/2.
- **Regret math:** PCFR+-style update with a canonical-DCFR discount (`crates/pkr-cfr/src/dcfr.rs`): `new = w_pos·max(r,0) + w_neg·min(r,0) + predicted_delta`, clamped at 0 (RM+). Momentum term γ = 1/√(t+1).
- **Storage:** `CompactRegretTable` (`crates/pkr-cfr/src/table.rs`): per infoset 6 actions × (1 × i32 regret + 1 × i32 momentum) + 6 × i64 strategy-sum = **96 B/infoset**, behind a `papaya` concurrent HashMap<u64, usize> with thread-local idx cache. Regrets stored ×1000 fixed point.
- **Parallelism:** `run_iterations_parallel(n)` runs `n` logical iterations per rayon dispatch (n=256 in trainer), each task accumulates `BatchItem`/`StrategyOp` vectors; merge → sort → dedup → parallel flush once per dispatch.
- **GPU:** a wgpu compute path (`gpu.rs`) exists for regret updates, **but the production trainer calls `flush_cpu_batch` — the GPU path is currently dead code**, and its WGSL shader still implements the old broken `(t/τ)^p` formula that the CPU path already replaced.
- **Trainer CLI:** `binaries/pkr-trainer` with `--iterations --capacity --checkpoint --checkpoint-every --bench-seconds` and per-street abstraction-table paths. `run.sh` = full pipeline (precompute → train 1M iters → export). `bench.sh` = throughput benchmark.

### 1.2 Abstraction (infoset hashing)

`KMeansAbstraction::get_infoset_hash` (`crates/pkr-abstraction/src/lib.rs`) hashes:
`FNV-1a(street ‖ history_signature ‖ cluster_id ‖ flop_bucket)` where:

- **Preflop:** 1,326 hands → u8 bucket via `preflop_abstraction.bin` (EHS² k-means, k=200 default).
- **Flop:** `C(52,5)×10 = 25.99M`-entry u8 table → EHS² cluster id (k=200); flop *texture* bucket (k=200, 10-bin EHS histogram features) mixed in.
- **Turn:** `C(52,6)×15 = 305.38M`-entry u8 table (~305 MB mmap) → cluster id.
- **River:** `hand_rank >> 6` (117 tiers) × board bucket (k=200).
- **History signature:** `(actions_this_street, num_raises, last_was_bet)` — collapses betting sequences into a ~16-bit key.

EHS itself = Monte-Carlo showdown equity over `EHS_SAMPLES` rollouts (default 1000; run.sh lowers to 10–100 for precompute).

### 1.3 Action abstraction (the 6 buckets)

`abstract_action_index()` (traversal.rs) / `abstract_action_index_static()` (state.rs):

| bucket | meaning | generated by `legal_actions_into`? |
|---|---|---|
| 0 | fold | yes |
| 1 | check / call | yes |
| 2 | bet < 0.5× pot | **never generated — dead bucket** |
| 3 | 0.5× ≤ bet < 1.0× pot | the 0.5× sizing only |
| 4 | bet ≥ 1.0× pot | **both 1.0× and 2.0× sizings collide here** |
| 5 | all-in | yes |

### 1.4 Runtime/export

- Blueprint = sorted u64 keys + u8 CDF per key (binary-search lookup in `pkr-runtime`, `file_header + key_count + cdf`), guarded by hash-algo + version checks. FMph is scaffolded but lookup is currently plain binary search (fine at <1 ms p99 for ≤ tens of MB).
- `pkr-export/src/translate.rs` already implements the **pseudo-harmonic action translation** (Ganzfried & Sandholm 2013) as a pure function, but **no bet-size anchors are stored in the blueprint**, so the runtime cannot actually use it correctly for off-tree sizes yet.
- `pkr-exploit` (opponent-modeling overlay: decayed histograms → archetype → bounded ±12% shifts) and `pkr-fuzz` exist but are **not integrated**.

### 1.5 Known-broken / known-missing (verified against source)

1. **Empty-bucket regret pollution & `v_σ` bias** — in `traverse()`, for the traverser, buckets with no legal action get `v[a]=0` and *still* receive a `BatchItem` with `delta = (0 − v_σ)·opp_reach`; worse, `v_σ` is computed including zero-valued empty buckets, which biases every real regret delta. Bucket 2 is *always* empty (§1.3).
2. **Bucket 4 mixes 1.0× and 2.0× pot** — when the opponent samples bucket 4, the code picks uniformly between two very different sizings; the trained probability belongs to neither.
3. **The Kuhn harness does not converge** (`docs/status.md` #4: exploitability flat at 0.27–0.28 while the average-strategy value converges) — its exploitability calculation is wrong, so the project currently has **no trusted exploitability measurement at all**.
4. **DCFR discount is inert beyond t≈10⁴ in f32** (`t^p/(t^p+1)` rounds to 1.0) — status.md admits production is "vanilla CFR with a warmup discount". Strategy-sum averaging is undiscounted.
5. **WGSL shader formula divergence** (dead code today, but a landmine if anyone flips the GPU path on).
6. **Checkpoint cadence** — `run.sh` uses `--checkpoint-every 10000`. At 38.7K it/s that is one ~1 GB write every ~4 s once the table is large; checkpoint I/O will dominate wall-clock. (Measured it/s numbers were taken without this path active.)
7. **No bet-size anchors in blueprint** → runtime cannot translate off-tree opponent bets (the pseudo-harmonic function has no inputs wired).
8. **Traverser expands illegal/empty buckets** → wasted tree branches (≈1/6 of traverser work on preflop nodes), removed by T0.2.
9. **Hand evaluator is 21× "sort 5 + combinadic + mmap read"** (`pkr-eval/src/lookup_fast.rs`) — correct but ~1–3 µs per 7-card eval; it is on the hot path at every terminal node and in every EHS rollout.

## 2. The M1 16 GB constraint model

### 2.1 Memory budget (measured components × current config)

| Component | Formula | @10M infosets, k=200/200/200 |
|---|---|---|
| Regret+momentum (`data`) | C × 12 × 4 B | 480 MB |
| Strategy sums | C × 6 × 8 B | 480 MB |
| `papaya` hash→idx map | ~10M × ~40 B (load factor) | ~400 MB |
| Thread-local idx caches | 8 × (1M × ~24 B) worst case | ≤ 200 MB |
| Batch/merge buffers (peak, 256-iter dispatch) | ~300K items × 16 B × 2 + sort scratch | ~20–60 MB |
| Abstraction mmaps (file-backed) | 26 MB flop + 305 MB turn + 2.6 MB river + 10.4 MB ranks | ~345 MB resident-bound |
| OS + toolchain + headroom | — | ~2 GB |
| **Total steady-state RSS** | | **≈ 2.0–2.5 GB of 16 GB** |

**Conclusion:** memory is *not* the binding constraint at the current abstraction size. It becomes one only if you push river/turn resolution up aggressively (see the capacity math in T2.2/T2.3). Apple file-backed mmap pages are evictable, so the 305 MB turn table costs real RAM only when touched; do **not** replace `memmap2` with `Vec` loads.

### 2.2 Compute model

- **1 iteration = 2 traversals.** Measured: 38.7K it/s @ 8 threads → ~3.35B iters/day.
- Per-iteration infoset *visits* (traverser decision nodes touched): `D̄ ≈ 40–150` (measure yours, §5.3) → **R ≈ 3–12M infoset-visits/sec** across both seats.
- Flush (sort+dedup+RM+ update) ≈ 30% of wall; traversal ≈ 70%. Levers: T1.2 (pruning, cuts traversal), T1.5 (flush scratch reuse), T1.3 (faster terminal evals).

### 2.3 Disk & thermals

- Checkpoint at 10M infosets ≈ **1.1 GB** (96 B × 10M + 16 B × 10M map) — keep at most 3 rolling copies, write every `≥ 2×10⁷` iterations (T0.5 fixes cadence).
- Blueprint export: 14 B/infoset → 10M infosets ≈ 140 MB; VPS target is <50 MB → T2.4 adds a visit-count export filter.
- M1 Mini sustains 8-thread load 24/7; no thermal derating needed. Run training in `tmux`/`screen`; the trainer is Ctrl-C-safe (resumes from checkpoint).

## 3. Executive answer: training time on this machine

Full derivation + how to measure the two unknowns on your box is in **§5**. Summary (stock code, 8 threads, 38.7K it/s, k=200 abstraction, ~10M infosets):

| Target | In-abstracted-game exploitability | Wall-clock (stock) | Wall-clock (after Phase 0+1) |
|---|---|---|---|
| "Smoke" (plays legal, recognizable poker) | n/a (coverage only) | ~30–60 min | ~20–40 min |
| **Playable** (beats scripted calling/folding bots comfortably) | ≲ 100–150 mbb/gn | **≈ 6–12 h** | **≈ 4–8 h** |
| **Good** (solid all-street coverage; sensible sizings; hard to bully) | ≈ 20–50 mbb/gn | **≈ 1.5–4 days** | **≈ 1–2 days** |
| Strong (diminishing returns; only if you have a week+) | ≈ 5–15 mbb/gn | 1–3 weeks | 4–10 days |

Plus one-time costs per abstraction config: **precompute ≈ 1–2 h** (turn table dominates; T1.4 cuts it to ~10 min) and **export ≈ minutes**.

Notes:
- The estimates assume the Phase 0 correctness fixes land **before** the big run (T0.2 changes what the regrets mean — training before it is wasted).
- Arena/bot-vs-bot winrate is dominated by *coverage* (never uniform-random on turn/river) and the *exploit overlay* (`pkr-exploit`), not by the last 20 mbb of blueprint exploitability — that is why the phase ordering is correctness → speed → abstraction → extras.
- Do not run past ~4 days: average-strategy convergence is O(1/√t); a second week buys ~2× lower exploitability. Retrain with a better abstraction instead (T2.2).

#### T0.1 — Disable or fix the divergent GPU regret path

- **Steps:**

     ```toml

     default = []
     ```

     ```wgsl
     var w_pos: f32;
     if t < TAU {
         w_pos = 1.0;

         let tp = pow(t, ALPHA);
         w_pos = tp / (tp + 1.0);
     }
     var w_neg: f32;
     if t < TAU {
         w_neg = 1.0;

         let tp = pow(t, BETA);

     ```

#### T0.2 — Legal-bucket action abstraction (fixes regret pollution + `v_σ` bias + mixed sizes)

This is the single most important correctness fix in the playbook. It changes what the regrets *mean*.

- **Goal:** (a) buckets contain exactly one concrete bet sizing each (injective mapping); (b) the traverser never expands buckets with no legal action; (c) strategy is renormalized over legal buckets before sampling/averaging; (d) no `BatchItem` is pushed for empty buckets.
- **Depends on:** nothing.
- **Files:** `crates/pkr-core/src/state.rs`, `crates/pkr-cfr/src/traversal.rs`.
- **Steps:**

  **Step 1 — change the concrete sizings so each bucket is injective** (`state.rs`, both `legal_actions()` and `legal_actions_into()`):

  ```rust
  // BEFORE (both fns): for &frac in &[0.5, 1.0, 2.0]
  // AFTER:
  for &frac in &[0.5, 0.75, 1.5] { ... }   // keep the all-in push unchanged
  ```

  Rationale: 0.5 → bucket 3 (0.5 ≤ f < 1.0), 0.75 → bucket 3 too. That still collides. So instead make the *mapping* 4-way with dedicated anchors. Replace the fraction loop with explicit sizings and update `abstract_action_index*` to match:

  ```rust
  // state.rs — concrete sizings (check path and raise path):
  //   raise: raise_total = to_call + pot * frac, frac in [0.4, 0.8, 1.6]
  //   check: bet = pot * frac,             frac in [0.4, 0.8, 1.6]
  for &frac in &[0.4, 0.8, 1.6] { /* unchanged structure */ }
  ```

  ```rust
  // state.rs + traversal.rs — the shared mapping, now injective:
  // bucket 2: 0 < frac < 0.6     (the 0.4 sizing)
  // bucket 3: 0.6 <= frac < 1.2  (the 0.8 sizing)
  // bucket 4: 1.2 <= frac        (the 1.6 sizing, non-all-in)
  // bucket 5: all-in (amount >= stack + street_bet)
  ```
  Keep thresholds *exactly* these in both `abstract_action_index` (traversal.rs) and `abstract_action_index_static` (state.rs) — they must be byte-identical logic.

  **Step 2 — legal-bucket mask + renormalization in `traverse()`** (`traversal.rs`). Replace the `action_counts`/`action_indices` build and everything downstream of it with:

  ```rust
  // 1. Build legal-bucket mask.
  let mut action_counts = [0usize; K];
  let mut action_indices = [[0usize; 10]; K];
  for (idx, action) in num_actions.iter().enumerate() {
      if let Some(a) = abstract_action_index(&action.kind, current) {
          if action_counts[a] < 10 {
              action_indices[a][action_counts[a]] = idx;
              action_counts[a] += 1;
          }
      }
  }

  // 2. Renormalize the table strategy over legal buckets only.
  let mut legal_mass = 0.0f32;
  for a in 0..K {
      if action_counts[a] > 0 {
          legal_mass += strategy[a];
      }
  }
  if legal_mass > 1e-9 {
      for a in 0..K {
          if action_counts[a] > 0 {
              strategy[a] /= legal_mass;
          } else {
              strategy[a] = 0.0;
          }
      }
  } else {
      // Unvisited infoset: uniform over *legal* buckets.
      let n_legal = action_counts.iter().filter(|&&c| c > 0).count().max(1);
      for a in 0..K {
          strategy[a] = if action_counts[a] > 0 { 1.0 / n_legal as f32 } else { 0.0 };
      }
  }
  ```

  **Step 3 — traverser branch:** replace the `for a in 0..K` value loop so empty buckets contribute nothing at all:

  ```rust
  for a in 0..K {
      let count = action_counts[a];
      if count == 0 {
          v[a] = f32::NAN;          // sentinel: illegal bucket
          continue;                  // NO BatchItem push, NO 0.0 value
      }
      let pick_idx = action_indices[a][rng.random_range(0..count)];
      current.apply_action_in_place(&num_actions[pick_idx]);
      let child_deck_idx = *deck_idx;
      v[a] = traverse(/* ... unchanged ... */);
      *deck_idx = child_deck_idx;
      current.undo_action();
  }

  let mut v_sigma = 0.0f32;
  for a in 0..K {
      if !v[a].is_nan() {
          v_sigma += strategy[a] * v[a];   // strategy[a] is 0 for illegal buckets anyway
      }
  }

  for a in 0..K {
      if v[a].is_nan() { continue; }       // never push regret for illegal buckets
      let delta = (v[a] - v_sigma) * opponent_reach;
      batch.push(BatchItem { index: idx as u32, action: a as u32, iteration: global_iteration, delta });
  }
  ```

  **Step 4 — opponent branch:** the sampled bucket must come from the renormalized `strategy` (which now puts 0 mass on illegal buckets). Replace the `sampled_abstract` selection with a rejection loop:

  ```rust
  let r = rng.random::<f32>();
  let mut acc = 0.0;
  let mut sampled_abstract = usize::MAX;
  for i in 0..K {
      acc += strategy[i];
      if r <= acc && action_counts[i] > 0 {
          sampled_abstract = i;
          break;
      }
  }
  // Float-rounding fallback: pick the last legal bucket instead of K-1.
  if sampled_abstract == usize::MAX {
      sampled_abstract = (0..K).rev().find(|&i| action_counts[i] > 0)
          .expect("at least one legal action exists at a non-terminal node");
  }
  let count = action_counts[sampled_abstract];
  ```

  **Step 5 — strategy-sum accumulation stays as is** (`strategy_batch.push` happens before renormalization? NO — move it *after* the renormalization block so the exported average strategy is over legal buckets):

  ```rust
  if let Some(idx) = traverser_idx {
      for a in 0..K {
          if action_counts[a] > 0 {          // only legal buckets
              strategy_batch.push(StrategyOp {
                  index: idx as u32, action: a as u8, prob: strategy[a] * reach_prob,
              });
          }
      }
  }
  ```
  (The `traverser_idx` lookup must happen before renormalization since `get_strategy_and_idx` fills `strategy`.)

- **Verification:**
  1. `cargo nextest run --workspace` — all green. Add this new test in `traversal.rs`:
     ```rust
     #[test]
     fn no_regret_pushed_for_illegal_buckets() {
         // Run one iteration with the real machinery; assert that for every
         // BatchItem, the (idx,action) pairs with action_counts==0 never appear.
         // Simplest check: count BatchItems per infoset <= number of legal actions.
     }
     ```
     (A presence-level assertion is enough: total `batch.len() <= strategy_batch.len() * K` and no NaN ever reaches `flush_cpu_batch`.)
  2. `./smoke.sh` end-to-end still green.
  3. `./bench.sh` — traversal share should drop measurably (~10–20% faster) because empty branches are gone.
- **Risk & rollback:** medium — this changes training semantics. Keep the old behavior behind `#[cfg(feature = "legacy_buckets")]` if you want a 1-day A/B. Golden hash vectors in `pkr-abstraction` are unaffected (hash inputs unchanged). **Requires a full retrain afterwards** (old checkpoints are semantically stale).
- **References:** bucket-deletion / partial abstraction soundness: Waugh et al., "Abstraction Pathologies in Extensive Games" (AAMAS 2009) — the "action abstraction pathology" this fixes.

     ```rust
         // at opponent nodes weight by opponent's AVERAGE strategy,

         // average the leaf value over deals.

         //   * using strategy_at (current regrets) -> fix to average_strategy_at
         //   * using max at BOTH seats' nodes      -> max only at the BR seat
         todo_eval(k)
     }
     ```
  2. Sanity anchors you must hit (use these as assertions, tolerance 1e-3):
     - uniform random strategy (all `average_strategy_at` = 0.5/0.5): exploitability ≈ **0.0933** (compute exactly: br(0)=1/18+1/3·... — verify numerically with an independent 5-line brute force over the 12 pure strategies of the BR seat; 12 pure strategies per seat × 6 deals is trivially enumerable).

#### T0.4 — Abstracted-game best-response exploitability checker for NLHE (the project's missing compass)

- **Goal:** every N training iterations, measure the blueprint's exploitability **in the abstracted game** (the game the CFR actually solves) and log it. This turns training from "run 1M iterations and hope" into "stop when the curve flattens".
- **Depends on:** T0.2 (so the tree it measures is the fixed one).
- **Files (new):** `crates/pkr-exploit/src/best_response.rs` (+ `pub mod best_response;` in `crates/pkr-exploit/src/lib.rs`), `binaries/pkr-trainer/src/main.rs` (wire `--eval-every`).
- **Why this is feasible on the M1:** the abstracted game has ~10⁶–10⁷ infosets but its *tree* (6 abstract actions, opponent buckets sampled) is small enough to **enumerate exhaustively with reach-weighted chance sampling**: an exact BR over the sampled abstracted tree with ~10⁷ sampled nodes runs in seconds in Rust — do it on ~200k sampled deals and you get ±few-mbb accuracy.
- **Steps:**
  1. Implement sampled best response in `best_response.rs`. Core signature:

     ```rust
     use pkr_contracts::{AbstractionBuilder, Evaluator};
     use pkr_cfr::table::CompactRegretTable;
     use pkr_core::state::{GameState, Action, ActionKind, Street};

     pub struct BrResult {
         pub exploitability_mbb: f64,   // in milli-big-blinds per game (mbb/gn)
         pub deals_sampled: u32,
     }

     /// Sampled-exploitability of the table's AVERAGE strategy.
     /// br_seat(s) = E_deal[ max_{a} Q(s, I_seat, a) ] with Q computed by
     /// recursing over the opponent's average strategy (chance-sampled).
     pub fn sampled_best_response(
         table: &CompactRegretTable,
         abstraction: &dyn AbstractionBuilder,
         evaluator: &dyn Evaluator,
         deals: u32,
         rng_seed: u64,
     ) -> BrResult { /* below */ }
     ```

  2. Implementation recipe (mirror `traverse()` structure, two passes per deal):
     - **Pass A (strategy collection):** for `deals` random deals (shuffle 9 cards like the trainer does: 2 hero + 2 villain + 5 board), run the same external-sampling recursion, but at *every* node of *both* seats record `(infoset_hash, bucket) → [opponent_avg_reach]` contributions... this is the heavy path. Simpler and standard for external sampling: run **BR traversal** — for seat `s`, walk the tree where seat `s`'s nodes are max-ed, opponent nodes sample from `get_average_strategy_into`, chance (runouts) sampled once per deal, accumulating `br_value[s]`. Repeat with seats swapped.
     - At each seat-`s` decision node: enumerate legal buckets (same renormalization as T0.2), evaluate each child once (their subtree is now BR-deterministic — memoize `Q` per `(infoset_hash, bucket)` in a `papaya`/`HashMap` local to the run), take the max, and return it.
     - Memoization makes the whole thing near-linear: each `(hash, bucket)` subtree is solved once ever.
     - **exploitability_mbb = ((br_0 + br_1)/2 − (gsv_0 + gsv_1)/2) × 1000 / bb**, where `gsv` (game value of the average strategy vs itself) can be computed on the same sampled deals by playing the average strategy against itself (or approximated by the CFR average payoff — log both).
  3. Trainer wiring (`main.rs`):
     ```rust
     #[arg(long, default_value_t = 0)] eval_every: u32,
     #[arg(long, default_value_t = 20_000)] eval_deals: u32,
     // in the loop, every eval_every iterations:
     if eval_every > 0 && done % eval_every == 0 {
         let br = pkr_exploit::best_response::sampled_best_response(
             trainer.get_table(), abstraction.as_ref(), evaluator.as_ref(),
             cli.eval_deals, done as u64);
         eprintln!("EVAL iter={} expl_mbb={:.2} deals={}", done, br.exploitability_mbb, br.deals_sampled);
     }
     ```
  4. Add `pkr-cfr` and `pkr-abstraction` to `pkr-exploit`'s `[dependencies]` (they are workspace crates; no cycle: exploit already conceptually sits above cfr — if a dependency cycle appears, move the module into `pkr-cfr::metrics` instead and keep `pkr-exploit` untouched).
- **Verification:**
  1. `cargo nextest run -p pkr-exploit` with a unit test that a **uniform-random blueprint** (fresh table) yields exploitability ≫ a **100k-iteration-trained table** on the same seed, and that two consecutive evals of the same table agree within 5%.

#### T1.1 — Integer-exact DCFR/linear discounting (make the discount actually exist at t > 10⁴)

- **Goal:** replace the f32 `t^p/(t^p+1)` (which rounds to exactly 1.0 for t ≳ 10⁴, making production training vanilla CFR per `docs/status.md` #2) with an exact rational discount computed in integer math, applied to regrets *and* to the strategy sum (currently undiscounted).
- **Depends on:** T0.3 (so you can *prove* on Kuhn that discounting still converges).
- **Files:** `crates/pkr-cfr/src/dcfr.rs`, `crates/pkr-cfr/src/table.rs` (`flush_cpu_batch`, `apply_strategy_batch`), optionally `run.sh` (new flag).
- **Steps:**
  1. Add to `dcfr.rs`:
     ```rust
     /// Exact discount w_p(t) = t^p / (t^p + 1) in integer domain.
     /// Supported: p = 0, 1, 2 (covers β=0 and α,γ ∈ {1,2}; DCFR's grid shows
     /// any α ∈ [1,2], γ ∈ [1,2] works; the paper's default α=1.5 rounds to 2
     /// with negligible loss — verified by the Kuhn harness in T0.3).
     #[inline(always)]
     pub fn discount_num_den(t: u32, p: u32) -> (i128, i128) {
         let t = t as i128;
         let tp = match p { 0 => 1, 1 => t, 2 => t * t, _ => unreachable!() };
         (tp, tp + 1)
     }
     ```
  2. In `table.rs::flush_cpu_batch`, replace the per-group `update_regret_pfr_plus` call with an integer-exact variant:
     ```rust
     let (an, ad) = dcfr::discount_num_den(iteration, 2);   // α = 2
     let (bn, bd) = dcfr::discount_num_den(iteration, 0);   // β = 0  → w_neg = 1/2 exactly
     // cur, mom are f32/SCALE today; switch the arithmetic to i64 fixed point:
     //   new_r = (cur_i * an + (ad - an) * POS_CAP? ) — simplest exact form:
     //   r_pos_i = max(cur_i, 0);  r_neg_i = min(cur_i, 0);
     //   disc_i  = (r_pos_i * an + r_neg_i * bn) / ad      (i64 division, exact enough)
     //   new_i   = disc_i + (delta * SCALE) as i64         (delta still f32 → fixed point once)
     ```
     Keep everything as **i64 intermediates** (i32 storage is fine: |r| ≤ 200 bb × 1000 × growth is bounded by the discount itself). Note the integer division introduces ≤1-lsb rounding per update — three orders of magnitude below the f32 failure it replaces. Momentum uses the same weights.
  3. Discount the strategy sum (currently identity — status.md #5): in `apply_strategy_batch`, per group apply
     ```rust
     let (gn, gd) = dcfr::discount_num_den(iteration, 2);   // γ = 2
     // sum_new_i = (sum_i * gn) / gd + (prob * SCALE) as i64
     ```
     This requires reading the existing sum before the fetch_add — do a `load` → compute → `store` per group (groups are unique-key after dedup, so race-free, same argument as the regret flush).
  4. Store the exponents in the checkpoint header? **No** — instead put them behind CLI flags on the trainer (`--alpha 2 --beta 0 --gamma 2`, defaults as above) and assert on checkpoint load that they match the run that wrote it (add two bytes to `PKRCKPT3`... **do not** — instead keep them process-local; mismatched resumes are caught by the T0.3-style sanity curve).
  5. Validate on Kuhn: run the `kuhn-experiment` matrix (canonical-f32 vs integer-exact α=2) — expect integer-exact to reach 1e-3 exploitability measurably earlier at large t and *never* NaN.
- **Verification:**
  ```bash
  cargo nextest run -p pkr-cfr -p pkr-testgames
  cargo run --release -p pkr-testgames --bin kuhn-experiment   # decreasing curve, no NaN
  ./bench.sh                                                   # no throughput regression > 3%
  ```
  Then a 1 h NLHE A/B (T0.4 checker enabled): discounted run must show lower `expl_mbb` at every checkpoint after ~10⁶ iterations.
- **Risk & rollback:** medium (numerics). The integer path is strictly more precise than the status quo; rollback = revert `flush_cpu_batch` to `update_regret_pfr_plus`.
- **References:** Brown & Sandholm, "Solving Imperfect-Information Games via Discounted Regret Minimization" (AAAI 2019, arXiv:1809.04040) — DCFR weights and the (α,β,γ,τ) grid; Linear CFR in the same paper.

#### T1.2 — FBRS-style regret pruning (the biggest single traversal speedup)

- **Goal:** stop expanding traverser actions whose regret is hopelessly negative. Published speedups on poker trees: **2–4×** at large t with identical final exploitability.
- **Depends on:** T0.2 (renormalized legal buckets), T0.4 (so you can verify convergence did not degrade).
- **Files:** `crates/pkr-cfr/src/traversal.rs`, `crates/pkr-cfr/src/table.rs` (expose one read helper).
- **Steps:**
  1. Expose in `table.rs`:
     ```rust
     #[inline]
     pub fn regret_scaled(&self, idx: usize, action: usize) -> i32 {
         self.load_rm(idx, action, RM_REGRET)
     }
     ```
  2. In `traverse()`'s traverser value loop (after T0.2), skip hopeless actions:
     ```rust
     // FBRS (Brown & Sandholm, NeurIPS 2015), simplified with an absolute
     // threshold: prune action a when its regret is very negative AND its
     // RM+ probability is zero. Freeze (don't update) the pruned regret.
     const PRUNE_WARMUP: u32 = 1_000_000;      // iterations
     let prune_threshold: i32 = -(400 * SCALE as i32);   // -400 bb in fixed point
     for a in 0..K {
         let count = action_counts[a];
         if count == 0 { v[a] = f32::NAN; continue; }
         if global_iteration > PRUNE_WARMUP
             && strategy[a] == 0.0
             && table.regret_scaled(idx, a) < prune_threshold
             && rng.random::<f32>() < 0.95 {
             v[a] = f32::NAN;                  // treated like illegal: no push
             continue;
         }
         // ... existing expansion ...
     }
     ```
     Notes: `strategy[a] == 0.0` is exactly the RM+-zero condition (regret ≤ 0). The 5% non-prune rate lets a truly recovering action re-enter measurement; FBRS's formal guarantee uses `r < −t·π̄⁻(I)·Δ` — the absolute threshold is the conservative common approximation (document it in a comment).
  3. The `v_sigma` loop and BatchItem push from T0.2 already skip `NaN` values — pruning needs **no further changes**.
- **Verification:**
  1. `cargo nextest run --workspace`, `./smoke.sh`.
  2. `./bench.sh` at 8 threads: expect ≥ 1.3× it/s once t > 10⁶ (bench runs are too short to see full 2×; the effect grows with t).
  3. A/B with T0.4: two 30-min runs (prune on/off), equal iterations; `expl_mbb` within noise (±10%).
- **Risk & rollback:** medium. If exploitability diverges from the non-pruned run, lower `prune_threshold` magnitude (e.g. −2000 bb) or raise the non-prune rate to 10%. Rollback = delete the 5-line guard.
- **References:** Brown & Sandholm, "Regret-Based Pruning in Extensive-Form Games" (NeurIPS 2015); dynamic thresholds: Brown & Sandholm (AAAI 2017).

#### T3.3 — Preflop chart validation + runtime fallbacks (half a day, protects everything)

- **Goal:** catch "structurally wrong preflop" and "uniform on unseen infosets" regressions before they cost a tournament.
- **Steps:**
  1. Script `scripts/preflop_sanity.sh`: loads `blueprint.bin`, queries the ~40 canonical preflop infosets (BU open/3-bet/4-bet, BB defend), prints action distributions; assert BU open ≥ 70%, BB 3-bet 8–20%, no preflop infoset uniform (max prob < 0.5) after 1M+ iterations.
  2. Runtime fallback policy for `lookup() == None`: preflop → pot-odds chart; postflop → fold vs bet, check otherwise, unless hand equity (via evaluator) > pot odds → call. Implement behind `SolverHandle::fallback_advice` so the host app never sees a panic.

## 5. Training-time estimate on the M1 (derivation + how to measure on your box)

### 5.1 The two numbers that decide everything

Training progress in external-sampling MCCFR is governed by **how many times each infoset gets visited**, not by the iteration counter. Two quantities:

- **N** — number of distinct reachable infosets under the current abstraction. With k=200 clusters / 200 flop buckets / 200 river buckets and the collapsed history signature, the reachable count is ~**5–15M** (the trainer's own `--capacity 10000000` + near-capacity warning is the evidence). You read it directly from the trainer log: `infosets: X` after it plateaus.
- **D̄** — average number of *traverser decision nodes* touched per traversal. You can read it from the phase profile: `PKR_PHASE_PROFILE=1` prints `nodes=` per dispatch; divide by (2 × iterations per dispatch). Expect **40–150**.

Infoset-visit rate:

```
R = it/s × 2 traversals × D̄
  ≈ 38,700 × 2 × 80      (stock code, 8 threads, D̄=80)
  ≈ 6.2M infoset-visits/second
```

### 5.2 From visits to quality

CFR's average strategy converges at ~O(1/√visits). Empirical mapping for a ~10⁷-infoset HU-NLHE-style abstracted game (consistent with published tabular CFR results and this repo's own roadmap estimate of "1–3 day meaningful blueprint"):

| Mean visits per infoset V̄ | Expected in-abstracted exploitability | Verdict |
|---|---|---|
| ~100 | 200–400+ mbb/gn | plays cards, folds too much |
| ~10³ | 100–150 mbb/gn | playable vs weak bots |
| ~10⁴ | 20–50 mbb/gn | **good** |
| ~10⁵ | 5–15 mbb/gn | strong, diminishing returns |

But visits are **not uniform**: preflop infosets get visited orders of magnitude more often than deep-line river infosets. The cold tail dominates wall-clock, so the honest model is:

```
t(target) ≈ κ × N × V_target / R ,    κ ≈ 10–30   (cold-tail skew factor)
```

### 5.3 Scenario table (N = 10M, R = 6.2M visits/s, κ = 20)

| Target | V̄ | Wall-clock (stock) | With Phase-0+1 (pruning ≥1.3× throughput, real discounting ≈1.3× better quality per visit ⇒ effective ≥1.7×) |
|---|---|---|---|
| Playable | 10³ | κ·10⁷·10³/6.2e6 ≈ **9 h** (range 4–12 h) | **≈ 5 h** |
| Good | 10⁴ | ≈ **3.7 days** (range 1.5–4 days) | **≈ 1.2–2 days** |
| Strong | 10⁵ | ≈ 5 weeks (do not) | ≈ 2 weeks (do not) |

One-time per-config costs: abstraction precompute ≈ 1–2 h stock / ~10 min after T1.4; export ≈ minutes. So **"implement the playbook, launch the run Friday evening, have a good bot by Sunday evening" is a realistic calendar**.

### 5.4 The measurement-first protocol (do this, trust nothing else)

1. After T0.2–T0.4 land, run 15 min: `./bench.sh` → your `it/s`.
2. Compute `D̄` from `PKR_PHASE_PROFILE=1` (`nodes` / (2 × iters per dispatch)).
3. Start the real run with `--eval-every 2000000 --eval-deals 20000`. The `EVAL iter=… expl_mbb=…` lines are the ground truth.
4. **Stop condition:** the checkpoint whose `expl_mbb` first falls under 50 and improves < 15% vs the previous checkpoint is your "good bot". Export it (T2.4 filter), sanity-check preflop (T3.3), ship.
5. If `expl_mbb` plateaus > 80 after 48 h: your `N` is too big for your throughput — revert T2.2 turn expansion (keep the river expansion), retrain.

### 5.5 What is *not* included in the estimate

- Implementing the playbook itself (~3–5 agent-days across all tasks; Phases 0+1 ≈ 2 days).
- Training the *first* smoke blueprint while tasks land (minutes each, do it often).
- Exploit-overlay integration (`pkr-exploit` wiring, ~1 day) — affects *arena winrate*, not training time.

## 7. Recommended end-to-end runbook (copy-paste for the big run)

```bash
# One-time (after Phase 0+1 land)
./smoke.sh                                        # end-to-end proof, small tables
cargo run --release -p pkr-eval --bin gen-fast7 -- fast7.bin   # if T1.3 done

# Abstraction build (T2.2 config; ~10 min after T1.4)
./run.sh --skip-train                             # or run steps 1-7 of run.sh manually

# The big run — tmux it. Resumes automatically from train.ckpt.
cargo run --release -p pkr-trainer -- \
    --iterations 4000000000 \
    --threads 8 \
    --capacity 15000000 \
    --centroids centroids.bin \
    --preflop-table preflop_abstraction.bin \
    --flop-table abstraction.bin \
    --flop-buckets flop_buckets.bin \
    --turn-table turn_abstraction.bin \
    --river-table river_buckets.bin \
    --rank-table hand_ranks.bin \
    --checkpoint train.ckpt \
    --checkpoint-every 20000000 \
    --eval-every 2000000 --eval-deals 20000 \
    --output blueprint.bin

# Watch progress; stop at the T0.4 plateau (§5.4 step 4).
# Then:
cargo run --release -p pkr-trainer -- ... --min-visits 32 --output blueprint_final.bin
./scripts/preflop_sanity.sh blueprint_final.bin
```

Expected calendar from a clean tree: **Phase 0 ≈ 1 day → Phase 1 ≈ 1 day → (optional T2.1/T2.2 ≈ 1 day) → training 1–2 days → export + sanity ≈ 1 hour. A good bot exists about 3–5 days after you start, with a playable one already available at the end of Phase 0 (overnight run).**
