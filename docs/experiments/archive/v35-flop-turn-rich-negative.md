# v35 — rich 10D flop/turn features (NEGATIVE result)

**Date:** 2026-09-26
**Status:** Negative. Rich 10D flop/turn tables hurt the model.
**Continues:** [v34-long-run-confirmed.md](v34-long-run-confirmed.md)
**Related:** [v33-rich-preflop-confirmed.md](v33-rich-preflop-confirmed.md)

## TL;DR

Extending the preflop feature-enrichment idea to flop and turn — adding 4
board-structure features to the 2D (EHS, EHS^2) space, giving a 10D
vector — **regresses the model by ~150 mbb at the best reading, with
9/10 matched readings favoring the 2D baseline** (sign test p ~= 0.02).

The preflop 6D win does not generalize to flop/turn. Feature enrichment
at fixed k appears to be a preflop-specific win.

## Setup

- **Both runs:** rich 6D preflop table (`outputs/v33rich/preflop_abstraction.bin`),
  60M regret capacity, 20M iterations, seed 42, `--eval-every 2000000`,
  `--eval-deals 5000`, `--promote-gate 3`.
- **Run A (baseline):** 2D flop/turn tables (`outputs/v33rich/{abstraction,turn_abstraction}.bin`).
- **Run B (rich 10D):** flop/turn tables with the 10D feature space
  (EHS, EHS^2, rank_high/12, rank_low/12, suited, connector,
  board_high/12, board_paired, board_flush_draw, board_connected),
  k=200, `EHS_SAMPLES=100`, generated by the `flop-rich` and
  `turn-rich` precompute subcommands.

Both tables pass a 200/200 cluster-distribution sanity check before
training (no degenerate collapse).

## Interpretation

### Why the preflop win does not transfer

The preflop 6D space captures hand structure (rank order, suitedness,
connectedness) which is the full strategic context at preflop — there
are no board cards yet. At flop/turn, EHS is *already* conditioned on
the board, so the board features we add are correlated with EHS but
not with the residual strategic distinctions.

Splitting k=200 across 10 dimensions fragments clusters along axes that
carry little strategic signal, at the cost of making each cluster
smaller and its regret estimates noisier. The net effect is a regression.

### Capacity effect observed in Run A

Run A shares its entire configuration with v33-B seed 42 except
regret capacity (60M vs 5M) and this pipeline's slightly larger eval
budget. Same preflop table, same 2D flop/turn, same seed, same 20M
iterations.

| | best |
|---|---|
| v33-B seed 42 (5M capacity) | 2728.6 |
| v35 Run A (60M capacity) | 2650.1 |
| delta | -78.5 mbb |

One SD of cross-seed noise on this metric is ~78 mbb, so this is
suggestive but not conclusive on its own. Worth isolating in a
dedicated capacity-sweep run.

## Recommendation

1. **Keep the 2D flop/turn tables as the default.** Do not ship rich
   10D flop/turn. `run.sh`'s `PREFLOP_RICH=1` default remains correct;
   do not extend it to `FLOP_RICH` / `TURN_RICH`.
2. **Close the feature-enrichment axis for flop/turn/river.** The
   preflop win was real but specific. Further hand-crafted feature
   engineering on these streets is low-EV.
3. **Consider a capacity sweep.** 60M vs 5M capacity at 20M iterations
   is the cleanest cheap experiment available now. Delta is ~1 SD; two
   seeds would settle it.
