## Section 2 — The single most important finding

**8-thread training was nondeterministic until `00a778d`.**

Two identical runs with seed 202, same config, 8 threads, diverged by
iteration 5M: infoset counts 1,005,012 vs 1,002,518 (0.25% different).
Every A/B in the project's history therefore had a hidden noise floor of
~30-50 mbb.

**Root cause:** `par_sort_unstable_by_key` calls in
`crates/pkr-cfr/src/table.rs` used non-total sort keys. Ties were
reordered arbitrarily per run. Since the sequential f64 fold is
order-sensitive, regret accumulations differed in low bits.

**Fix:** appended the value's bit pattern as a sort tiebreaker.

**Verification:** two fresh 8-thread runs, 3M iters, seed 202:
`exploitability.csv` is byte-identical. (The `metrics.csv` files
DIFFER — but only on wall-clock / timing columns, which is expected.
See Section 5.)

**Implication:** every future A/B is trustworthy at any thread count.
A/B deltas down to ~50 mbb are now resolvable. Before this fix, the
training-side experiments used `--threads 8` and had non-reproducible
small deltas.

### 5.2 Range-aware subgame solving — the 3-hour failure

Three attempts to make the subgame hook use the actual opponent range
(instead of uniform). All reverted. Detailed below so the next agent
does not repeat.

**Attempt 1: tracker threaded at every node.** Walkers carried a live
`RangeTracker`. Each `apply_action` costs 311 us (verified via
`bench_tracker`). With ~10K nodes/deal x 100 deals x 16 BR iterations,
that is 10+ hours per e2e eval. Killed.

**Attempt 2: history-replay design.** Walkers carried `Vec<WalkStep>`
instead. At each hook call site, replay the history through a fresh
tracker. Correct in principle (O(history_len) per hook call).
Implementation failed: the walker had 6 undo sites, 4 apply sites, and
2 advance sites. Adding history push/pop to all of them via pattern-
matching patches left a push/pop mismatch. History accumulated to 100+
actions per deal, causing `advance_street_in_place` to hit
`unreachable!()` when the state's street was already River. Reverted.

**The correct fix (design doc exists):** `docs/roadmap/range-aware-solving.md`
describes a `Traversal<'s, 't, 'd>` wrapper that owns both the state
and the history and exposes atomic apply / undo / advance_street
methods. The wrapper IS ALREADY WRITTEN (see
`crates/pkr-exploit/src/best_response.rs` lines ~77-145) but is not
wired into the walkers. Integration is a ~2h deterministic refactor
when done in one pass, not the 3 half-patterns we tried.

**Next session should not attempt this without committing to the
Traversal-first approach.**

### 5.3 Subgame e2e regression

With uniform ranges, adding river subgame solving regresses e2e by
+644 mbb at 100 deals (+1755 at 500). This is entirely a uniform-range
artifact: the solve optimizes P0 for a distribution the blueprint-P1
opponent doesn't play. Fixed by the range-aware piece above.

The per-subgame POC (+26 turn, +43 river) is still valid.

## Section 7 — Things NOT to retry

1. **Threading RangeTracker through walkers by pattern-matching patches.**
   Use the `Traversal` wrapper. See §5.2.
2. **Launching long-running tests without a small-scale timing check.**
   `bench_tracker` saved us; the 10-hour e2e could have been avoided by
   running the tracker 500 times and reading the per-call cost.
3. **Deleting `target/release/` while a launcher is mid-chain.** The
   launcher's next spawn will fail with `No such file or directory`.
   Free disk by removing individual checkpoint files instead.
4. **Reading `--eval-every 5000000` runs against `--eval-every 3000000`
   runs as if readings are comparable.** They aren't. Only compare at
   the same `done` value.
5. **Touching watchexec.** The user runs watchexec on other repos.
   Never `pkill -f watchexec`. Use targeted pid-kills only.
6. **Assuming metrics.csv byte-identical implies exploitability.csv
   byte-identical.** They can diverge on timing columns. See §5.1.

## Section 8 — Environment and dev-loop discipline

### Launch pattern that works

```bash
# Write a small launcher script that uses `exec` to replace itself:
cat > /tmp/launch_x.sh << 'SH_EOF'
#!/usr/bin/env bash
cd /Users/adm/Documents/Repos/pkr-sota
exec ./target/release/pkr-trainer <args>
SH_EOF
chmod +x /tmp/launch_x.sh
nohup /tmp/launch_x.sh > out.log 2>&1 &
PID=$!   # == the trainer pid thanks to exec
```

### Dev-loop blocking avoidance

- `wr.sh` must return in < 5 seconds. Any long-running thing goes to
  `nohup + disown` and writes its pid to a file.
- Status checks are a separate one-liner. Examples in
  `scripts/analysis/` if it exists, otherwise ad-hoc.
- Never `wait` on a nohup'd process from wr.sh.

### Commands that are safe

- `ps -Ao pid,comm | awk '$2 ~ /pkr-trainer$/ {print $1}'` — robust
  way to enumerate trainer pids (no grep self-match).
- `diff a.csv b.csv` — cheap determinism check.

### Commands that broke things this session

- `pkill -f watchexec` — DON'T. Kills user's other-repo watchers.
- `pkill -f e2e_subgame` — killed a legitimate test mid-run.
- `rm -rf target/release` — killed a running launcher's next spawn.
- `grep -c "tracker`'d" ...` — shell quote errors on backticks.
